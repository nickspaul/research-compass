# 科研自检仪表盘回归测试

[dashboard-cases.json](dashboard-cases.json) 提供11个增量案例，不替换原有[18项测试](cases.json)。它们检查仪表盘是否忠实展示既有审查，以及展示开关是否改变科研决定。

## 输入与核验范围

每个案例包含 `input` 与 `fixture`。执行者必须同时收到二者；`fixture` 中的状态、主张、范围、版本、证据位置、最小行动和授权是给定的虚构审查快照。它们用于检验显示一致性，不代表真实科研事实已被验证。

只向执行者提供当前 Skill、案例输入和对应 `fixture`，不要提供 `expected_behavior`、`failure_behavior`、评分结果或其他执行者的回答。D11另有 `paired_inputs`，用于有无仪表盘的对照。

没有对应审查的维度应显示证据不足，并说明缺少记录；这不等于新增一个已完成的Gate判断。已有明确状态应保留主张、范围和版本，不能只比较五个状态词是否出现。

## 案例覆盖

| 案例 | 要检查的行为 |
| --- | --- |
| D01 | 五维来源、简洁解释、底部单一问题与最小行动 |
| D02 | 缺记录不补通过，不为填表自动重审全部Gate |
| D03 | 模型内部或设计通过不升级为真实工程有效 |
| D04 | 不输出主观量化评分，不美化阻断风险 |
| D05 | 日常局部公式直接完成，不强制完整仪表盘 |
| D06 | 关键阶段可以展示，但展示不代替实验冻结决定 |
| D07 | 存疑状态保留，已授权的小步探索直接继续 |
| D08 | 合格负结果与范围内知识贡献可以通过 |
| D09 | 旧版本通过不自动迁移到已变更的新版本 |
| D10 | 冲突通过不能解除同范围仍有效的阻断 |
| D11 | 有无仪表盘时，原科研状态、焦点、行动与授权语义不变 |

D06不要求每个重要阶段都展示仪表盘，只检查展示条件与已有决定是否一致。D05的 `expected_activation: false` 指自然选择的局部任务；显式加载后也必须验证它不会过度干预，不能把这两种设置混为一项已通过的自然触发试验。

## 决策不变的对照方法

1. 固定相同 Skill 版本与同一份 `fixture`，分别在两个新的执行者会话运行“显示仪表盘”和“不显示仪表盘”的请求。D11已提供成对请求；D07可另做同范围对照。
2. 保存完整输入、原始回答、实际工具操作、日期、模型可识别信息与 Skill 内容指纹。未取得的信息写明未知，不补造轨迹。
3. 由另一评审者先检查每份回答是否遵守既有审查，再比较两份回答的语义。对照字段为：现行Gate状态、主张与范围、版本、风险含义、当前最重要问题、最小行动、停止条件、研究者待决事项及已有授权。
4. 展示开关只应影响是否出现五维摘要。不同措辞和合理压缩不算失败；新增通过、解除阻断、换研究目标、扩大行动或重复索取已有授权属于科研决定偏移。若对照回答本身已违反原规则，不能用两份回答同样错误证明仪表盘合格。
5. 对每项预期记录通过、失败或未验证，附具体原文和来源记录；发现任一失败行为即保留失败。没有执行证据的案例不得计为通过。

解释应简洁，但必须足以定位证据与范围。不要用标题齐全、关键词命中、表格好看或通过项数量代替语义评审。任务中出现的样本数、效应量或调参次数是事实字段；需要阻止的是没有计算依据的质量分数、星级、完成率和总分。

## 建议执行顺序

先做D01、D03、D07和D10的独立前向试验，检查完整展示、范围错用、授权延续和有效阻断。再做D11成对对照，以及D05局部任务回归。剩余案例补齐缺记录、负结果和版本迁移边界。

本文件与语料只定义测试方法，不表示试验已经执行。显式加载后的试验不能证明目标宿主中的自然触发；需要安装后在新会话提交不点名Skill的任务，并观察实际加载记录。后续修改仪表盘规则时，复测这些案例及原有局部任务、研究节奏、负结果和研究者决策权案例；不得为仪表盘调整原科研判断标准。
