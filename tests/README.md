# Research Compass 验收测试

[cases.json](cases.json) 包含18个案例：用户要求的10项验收、海上搜索集成审计、3项负触发测试，以及授权探索、终点变更、数据泄漏和理论构造边界测试。每项给出输入、预期行为、失败行为与验证方法。

1.1.0另增[科研自检仪表盘测试](dashboard-README.md)及[独立语料](dashboard-cases.json)，验证展示前后的Gate状态、主张范围、风险和授权不变。原18例与原始验收记录保留为历史基线；新增执行结果见[仪表盘验收记录](dashboard-validation-report.md)。

## 分开记录三类验证

| 验证 | 能回答的问题 | 不能证明的事项 |
| --- | --- | --- |
| 文件与结构检查 | frontmatter、引用、文件编码及案例字段是否完整 | 模型是否理解或遵守规则 |
| 显式加载后的行为试验 | 在给定输入与材料下，回答是否符合行为约束 | 安装后的自然触发、真实数据结论或长期可靠性 |
| 安装后的自然选择测试 | 未点名Skill时是否在合适任务中加载 | 在其他模型、版本和上下文中的普遍可靠性 |

T08同时测试新会话中的局部任务，以及科研上下文已激活时的不过度干预。T12至T14需要观察宿主的实际技能选择或读取记录；仅看到回答没有提到技能名称，不能确定技能没有加载。

## 独立行为试验

1. 使用新的评估会话，只向执行者提供Skill位置、本案例的 `input` 和完成任务所需原始材料。不要提供 `expected_behavior`、`failure_behavior`、过去答案或审查结论。
2. 显式加载试验可使用：`请使用指定目录的 research-compass Skill 完成以下请求：<input>`。自然选择测试只提供 `input`，不要点名或预先加载Skill。
3. 保存完整输入、原始回答、工具操作、执行日期、宿主与模型信息、Skill版本或内容指纹。无法获取的运行信息写为未知。
4. 由另一评审者按可观察决定评分，每项判为通过、失败或未验证，并引用回答或工具记录中的证据。一个案例的所有预期行为都满足、未出现任一失败行为，才可判为通过；缺少执行记录或无法观察关键行为时判为未验证。
5. 记录失败对应的具体决策，例如“将继续探索授权误记为Gate通过”。不要用关键词命中、模板标题齐全或回答长度代替行为评分。

集成案例T11的原始材料就是输入中的假想陈述。执行者不得去当前项目寻找相似结果以补充题设。核对五Gate七字段时，允许用表格或等价结构表达；还应检查状态与行动是否一致。题设中的5,760、80.51%和19.49%不因被模型复述而成为已核验实验结果。

T16的文件变更复测应在临时目录使用虚构卡片副本，先保留原始快照，再检查变更和日志。不要为了测试而更改真实科研记录。T10和T15无需启用付费资源；以输出和工具记录判断授权范围即可。

## 结果记录

每次试验至少记录下列字段，可直接写入独立测试报告：

```text
case_id:
run_date:
skill_version_or_fingerprint:
host_and_model:
setup: explicit-load | natural-selection | active-context
input_record:
raw_response_record:
tool_record:
assessment: passed | failed | not-verified
observed_evidence:
unverified_items:
reviewer:
```

本文件定义测试方法，不表示测试已经执行。实际执行结果以附带运行证据的测试报告为准。一次独立模型试验只能支持相应情境的行为结论，不能据此声称自动发现机制、跨模型稳定性或长期科研诚信已获验证。

## 部署后回归

在目标宿主安装后，先用3个独立新会话重复正触发、负触发和局部任务测试，保留每次原始记录。再安排以下回归：

- 第一次真实选题协作后，复测T01、T07、T15和T18，检查是否既审查前提又允许已授权探索。
- 第一次实验冻结或结果复盘后，复测T05、T09、T16和T17，检查证据身份、时间顺序及失效回退。
- Skill、模型或宿主更新后，复测全部18例；对曾失败案例增加一个不同领域的变体，检查修正是否只记住了海上搜索措辞。

收集研究者对误触发、漏触发、重复确认和错误放行的反馈。先定位失误发生在描述、路由、Gate判断还是授权解释，再做最小规则修正。新增测试应复现已观察的问题，避免用越来越长的通用禁令替代诊断。
