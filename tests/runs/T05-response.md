建议先做一轮有固定上限的配对试验，检验认证器的增益是否可能达到 2 个百分点，同时排除“只是更少行动”的解释。以下是**探索性方案草案**，不把小样本中的零损失当成安全性确认。

你的核心假设和“至少提高 2 个百分点”已由本条请求明确给出，沿用它们。还需明确收益损失事件的工程阈值和样本预算，不能由我代填成既定决定。

## 比较与预算

每个场景同时运行以下方法，并保留配对关系：

| 方法 | 用途 |
| --- | --- |
| 认证器方案 C | 待检验方法；候选生成、认证和追加抽样合计不超过 B 个模型样本。 |
| 简单重采样 R | 主要对照；可使用完整的 B 个模型样本，按开发阶段固定的简单规则选择动作。 |
| 保持原方案 K | 诊断保守策略是否已经取得相同风险表现，并量化实际改进空间。 |

两种主动方法使用相同先验、观测、可行域、执行约束及调参次数；共同随机量尽量配对。等样本不代表等计算，另报运行时间和内存。认证器若额外取样，必须从 B 中扣除；超预算或超时按预先规定的失败／回退规则记录，不能删除该案例。

在一小部分开发案例上，可对 C 的同一候选和样本记录关闭认证 veto，检查收益来自哪里；它只作机制诊断，不替代可自由使用全部 B 的 R。

## 场景与最小规模

建议上限为 **20 个开发场景加 60 个未用于调参的评估场景**；这是控制首轮成本的提案，没有功效计算依据，不能保证识别 2 个百分点或稀有损失差异。

开发场景只用于检查实现、固定超参数、预算分配、场景权重和分析程序。随后锁定版本，评估场景一次性完整运行，不按中间效果扩样或调参。若已有数据参与过方法选择，它们只能进入开发部分，不能重新标成未触碰评估集。

评估场景预先覆盖三类条件，各 20 个：常规条件、认证器容易退化为大量拒绝的高不确定性条件、一个可能改变方法排序的模型失配条件。具体范围应由现有任务依据确定，不能按哪组结果好看来选。没有目标场景频率依据时，等权汇总只代表这个人为构造的测试集合，分层结果也要保留。若同一基础场景派生多个运行，按基础场景作统计单位，不能把派生次数当作独立样本。

## 指标与判定

以一次完整搜索任务为观察单位，固定搜索时限和发现判据，估计配对发现率差：

\[
\Delta_D=P(\mathrm{发现}\mid C)-P(\mathrm{发现}\mid R).
\]

目标为 \(\Delta_D\ge 0.02\)，这里是绝对百分点差。

先固定收益损失的参考方案、评价时限、单位及工程阈值 \(h\)，再定义 \(E_m=1\{L_m>h\}\)，比较

\[
\Delta_E=P(E_C=1)-P(E_R=1).
\]

按你当前的“不增加”要求，目标是 \(\Delta_E\le0\)。若工程上允许一个正的风险差界值，那是对原假设的实质修改，需要你明确选择，不能默认换成较宽松的非劣性标准。

同时报告行动、保持、拒绝比例，平均收益损失及严重事件明细、计算成本、不可行／超时和完整分母。这样能检查发现收益是否被保守策略或少行动解释。

分析保留配对和预定场景权重。冻结前选定适合小样本配对二元结果的风险差区间方法，并检查其零事件处理；不能把零事件 Bootstrap 得到的零宽区间作为保证。为了同时判断两个条件，可预先使用各自 97.5% 的单侧界限，给出至少 95% 的联合覆盖保障，前提是各区间方法和采样假设成立。

判定规则预先固定：

- **支持该范围内的假设：**发现率差下界至少为 0.02，且损失事件率差上界不大于 0；预算与数据检查合格。
- **不支持原目标：**发现率差上界低于 0.02，或损失事件率差下界大于 0。保留负结果，检查是否有清楚的失效边界。
- **证据不足：**其他情况，包括点估计达标但区间跨界。两组都没有损失事件，通常仍不足以证明事件率没有增加。

不显著不等于等效。首轮若无法分辨，使用它估计下一轮所需样本量；若涉及稀有损失，可能需要另一种验证设计，不能靠继续追加有利种子解决。
