# Research Compass：科研罗盘

AI辅助科研的真实性、创新性、证据质量与研究节奏控制系统。

科研罗盘帮助研究者判断当前问题是否值得研究、现有证据能支持什么，以及下一步最值得做哪项验证。它支持明确限定的理论研究、受控基准和有风险的探索，也保留不支持原假设的结果。

## 安装和调用

完整复制 `research-compass/` 文件夹，保持 `SKILL.md` 与参考文件的相对路径。运行 Skill 无需 Python、网络服务或额外依赖；核验外部文献和原始数据时，使用宿主已有工具。缺少工具时必须说明尚未核验。

Codex 项目内安装：复制到 `<项目目录>/.agents/skills/research-compass/`。个人安装：复制到 `~/.agents/skills/research-compass/`。同名副本不会合并，选择一个安装位置。安装后检查技能列表；未出现时重启 Codex。这些路径和发现行为依据 [OpenAI 官方技能文档](https://learn.chatgpt.com/docs/build-skills)，核对日期为 2026-10-28。

本交付目录是可搬移的源包，并未写入个人技能目录。也可在当前会话直接提供 `SKILL.md` 路径，请 Agent 读取后执行。安装后的显式调用方式为 `$research-compass`；支持技能选择器的宿主可在选择器中选取。自动选择由宿主实现，取决于描述匹配和可见技能列表。

## 何时使用

在科研选题、研究方案设计、仿真实验规划、结果分析、论文贡献审查和研究决策复盘时自动考虑本 Skill。普通翻译、基础润色和无关任务不触发。仅核对公式、检查代码或整理结果时直接完成局部工作；发现具体科学风险时再启用相关 Gate。

协作模式默认只处理当前阶段的一两个问题。新想法从科研问题卡开始；收到完整论文、报告、方案或仓库且用户要求科学质量评审时，进入独立审计模式。审计按十原则检查，区分已核验事实、作者声称、审查推断和未证实怀疑。

## 五个闸门如何使用

| Gate | 需要回答的问题 |
| --- | --- |
| 1 问题真实性 | 问题从哪里来，有什么独立依据，受控构造有什么研究价值？ |
| 2 创新与知识增量 | 相比已知工作和简单替代，新增了什么可检验知识？ |
| 3 方法与实验设计 | 假设、基线、反证、统计设计和确认数据隔离是否足以检验主张？ |
| 4 结果与证据 | 结果有什么实际意义，替代解释是否被排除，适用范围在哪里？ |
| 5 知识贡献与论文主张 | 可靠发现、推测和不可宣称内容分别是什么？ |

每个已评估 Gate 输出七项：核心问题、证据及来源、未证实假设、反例或替代解释、状态、最小下一步、研究者待决事项或已有授权来源。状态为通过、存疑、阻断或证据不足。状态限定到具体主张与范围，材料变化时可回退。

研究者可以选择带风险继续探索；证据状态仍按材料保留。已授权且范围未变的低成本工作直接执行。核心问题、关键假设、确认实验冻结、主要终点、核心贡献、重大投入和重要数据修改等决定需有研究者的明确选择。先准备可审阅方案，只在缺少实质决定时提出决策请求。

## 实际调用示例

### 科研自检仪表盘

1.1.0新增简洁Markdown仪表盘，展示问题真实性、创新性、模型有效性、证据质量和知识贡献。每维沿用对应Gate的有效判断，附一句带来源和范围的解释；底部突出一个关键科学问题与一个最小行动。没有对应审查项就标证据不足，不生成量化评分。

仅在选题去留、确认设计冻结前、主要结果复盘或贡献定稿等重要节点，或用户要求时展示；日常局部任务不强制展示。已有授权、阻断、负结果及最小下一步保持原意，模型内部通过不能写成现实有效。

```text
$research-compass 根据现有Gate记录显示科研自检仪表盘，
保留各项来源、适用范围和已有授权，突出当前一个关键问题及最小行动。
```

详细对应规则见[仪表盘说明](references/research-dashboard.md)，可复用[Markdown模板](assets/research-dashboard.md)。仪表盘展示不要求重新运行五个Gate。

### 新想法

```text
$research-compass 我想用强化学习改善无人艇协同搜索。
目前只有自建仿真中的局部失败案例。请先做科研问题卡，
找出最值得验证的前提和一个低成本反证实验。
```

### 实验设计

```text
$research-compass 请审查这个仿真实验计划的 Gate 3。
现有材料是 design.md 和 baseline_budget.csv。
请检查基线预算、主要终点和开发/确认数据隔离，准备实验前承诺卡。
确认实验尚未冻结；这轮只审查设计。
```

### 已有结果与贡献审计

```text
$research-compass 请独立审计 report.md 和已提供的实验记录。
重点判断“零负收益”是否支持决策优势，以及简单基线是否削弱方法必要性。
给出能保留的知识、需要补做的最小验证和不能宣称的内容。
```

### 已授权探索继续

```text
$research-compass 我已接受问题卡里的外部有效性风险，
同意按记录 D-04 做最多 20 个场景、10 分钟的小规模探索。
请在这个范围内执行，保留失败结果；不要改确认实验或主要指标。
```

### 局部任务

```text
$research-compass 只检查这个恒等式是否成立：
A-C = (A-B) + (B-C)。暂不评估整项研究。
```

最后一例应直接完成代数核对；局部恒等式不提供因果解释。

## 连续协作与记录

沿用项目已有记录位置。允许写文件且没有既有位置时，在项目内使用 `research-notes/`，按需复制卡片并追加决策记录。只读审计直接返回记录，不创建目录。日志记录实际证据、决定、授权范围、接受的风险及变更；不保存推测的历史批准。

内部实验前承诺与公开预注册分别记录。分析开始后的终点变化保留时间与理由，必要时重新获得独立确认；不得倒填成事前预测。新证据使前提失效时重开受影响 Gate，其他已授权工作可继续。

本地结构检查仅需 Python 3.9 或更新版本，在包所在目录的上一级执行：

```text
python research-compass/tests/validate.py research-compass
```

脚本只读文件，检查本包采用的 frontmatter 子集、名称与目录、必需资源、维护文档的相对链接、Markdown 表格/围栏及测试语料结构。原始试验回答保留当时的本机路径，不作为可搬移引用。脚本不运行模型，不判断科学主张，不证明自动触发。真正的行为验证需使用测试输入运行 Agent，逐项审阅其回答与操作记录。详细结果和未测部分见[验收记录](tests/validation-report.md)。

本包遵循 [Agent Skills 公开格式规范](https://agentskills.io/specification) 的目录、frontmatter 与渐进加载约定。本地检查器不替代完整规范库或所有宿主的兼容性测试。

## 根据反馈改进

记录实际输入、技能版本、输出、期望动作和造成影响的偏差。优先修正可复现的漏检、无依据通过、过度阻拦或重复确认，将脱敏情境加入回归语料。先判断问题属于描述匹配、参考规则还是模板负担，再修改对应位置，避免每次失败都增加全局规定。

规则或触发描述变化后，重新检查正触发、负触发、局部任务和授权延续。每类在全新会话中至少重复三次，检查是否同时改善漏检与误触发。保留旧版结果作对照；研究者反馈改变操作偏好时，不改变事实来源、证据独立性和历史记录。
